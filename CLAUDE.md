One big HTML file (`Flamey_s_Official_Animation_Studio_extensions.html`, ~1.6 MB). All scripts are inline `<script>` tags. Joel (the owner) works in HTML5 canvas and browser formats and likes direct, short feedback.

## Checking your work
- Syntax: pull the inline scripts out into one file and run `node --check` on it.
- Behaviour: Playwright (chromium) against the file. Call `bkEval({t:'blockname', v:[...]})` directly. To draw a block: `bkBlockEl({t, v}, {palette:true})` into a div, then screenshot.
- To open the real editor in a test: push `"blocks"` onto `EXI`, add a `<div class="v v-blocks">` next to `.v-edit`, call `go('blocks')`, then `document.querySelector('.bkpanel').__setFull(true)`. Stub `upgLocked` to return false.
- Loops only run when `playing` is true and `EXI` includes `"blocks"`.
- The network is blocked in the test sandbox. Mock `window.fetch` for the definition block (`lookdef`).

## How blocks work
- `BLK` defines each block: `{cat, shape, tpl, a, run, [col], [lazy], [loop]}`. `tpl` uses `%1 %2` for inputs. Shapes: `hat`, `cmd`, `cap`, `c` (one mouth), `c2` (two mouths, `because`), `c3` (three mouths, `trycatch`), `rep` (round), `bool` (pointed), `list` (square).
- `a` entries are `[type, default, options]` with types `num`, `str`, `text`, `bool`, `menu`.
- The tray order is the key order of `BLK` within each category. `BKCAT` holds the categories: watch, settings, operators, control, keep, commands, function, rigs, audio, looks, edit, variables.
- `BKS` is the list of scripts `{x, y, b:[blocks]}`; a block is `{t, v:[values or {r: block}], s, s2, s3}`. Saved to localStorage `oss_blocks`. Variables in `oss_blkvars`.
- Running: `bkEval` / `bkVals` / `bkRunList` / `bkRunStack`. Control flow is done with thrown sentinels: `BK_STOP`, `BK_BREAK`, `BK_CONT`, `BK_RESTART`, `BK_FAIL`, `BK_KILL`, and return objects `{bkRet:true, value}`. `bkRunList` rethrows these; loops use `bkLoopBody`.
- Frame hats are `whenframe`, `whenfromto`, `whencond` (see `bkFrameHat`, `bkHit`); `ineditor` runs when a project opens. `bkPlayFrame` fires hats while playing and `bkExportFrame` while exporting (`bkExp` holds export state).
- `bkTry` counts open `try` blocks; `bkFast` is above 0 inside `fast`; `bkKill` is the set of stopped command blocks; `BKCMD` holds running commands.
- Drag and drop: `bkFindSnap` (a cap block can only go at the end of a list or into an empty mouth), `bkDragStart`. The snap height `gh` has to be measured before the ghost is removed.
- Fullscreen editor: anything appended to `document.body` is hidden while fullscreen. Append to `document.fullscreenElement || document.body`.

## Decisions Joel made (keep these)
- Coordinates in every block (Rigs `x of`/`y of`, Particles, Hitbox): 0,0 is the middle of the stage, x goes right, y goes up (like Scratch). Any new block with x or y must do the same. Inside, particles (`PTS`) are kept in canvas pixels and converted at the blocks; hitbox points are kept in block coordinates and `hbToStage` converts them for drawing and touching.
- Blocks are for creating things that are not assets or characters, and for enabling things. No blocks that make assets or characters (Joel makes those himself). The Rigs, Make assets, Edit text and Fonts blocks were removed for this reason; only the original `x of ()` and `y of ()` stay in Rigs. Converter, Zipper and Scenery don't need blocks (Scenery only gives assets and backgrounds to use in Edit video). Effects doesn't need blocks either: extra effects come as an extension turned on in the Extensions page.
- Blocks are also for working around things that have bugs, and for things that can't be made without blocks. The test for a new block: if Joel can already do it himself in the studio, no block; if he can't, add one.
- No "stop all" block; `stop` ends only its own script. Two `stop` blocks must not stack.
- `<>` truth rule (`bkTruthy`): a number anywhere in the text decides (0 is false); otherwise words are true unless "false"; an empty box is false.
- `infinity of`: repeat M = N+1, L = M^M until L carries E (stop at 1e21); if it goes infinite, the previous step is the answer.
- `() of ()` is the mod block. `() uses ()` has the text first, the part second. The grey keep blocks and the yellow command blocks live in their own categories; the `when <>` hat is the only block in Function. The C-shaped `when <>` is an if block and stays in Control.
- `() out ()` and `() in ()` were dropped on purpose.
- Audio blocks (`talk with audio` = play once, `add sound … as a background` = loop under the whole video, `play sound … about () times` = whole sound back to back N times, `all sounds`) must be in the exported video, because videos go to YouTube. A block never restarts its sound while it is still going (`BK_SND`); while exporting, sounds go into the recording through `bkSndOut`.
- Weather extension (`id: "weather"`, add-on for Effects): adds a Weather group to Add an effect. 🌧 Rain is drawn in code in the style of Joel's hand-drawn rain GIF, not a copy of it (Joel asked for that): his blue #009fff, thin round-ended streaks slanted about 9°, short and long drops, light at the start and then heavier (`rainDraw`). Strength = number of drops; See-through (`e.see`, default 35%) makes it faint; Angle (`e.ang`, -45° to 45°, default 9°) tilts it. When its last frame passes, no new drops start but the falling ones finish (`fxOn`, `RAIN_TAIL`). ❄ Snow (`snowDraw`): round white flakes with a soft blue edge, falling slowly and swaying; same Strength / See-through (default 15%) / Angle (default 0°) sliders; falling flakes finish after it ends (`SNOW_TAIL` 8 s). ⚡ Lightning (`lightDraw`): at random times a jagged bolt (sometimes with a branch) and a flash that flickers once and fades; Strength = how often (3.2 s to 0.6 s apart), See-through = brightness (default 0%), Angle = lean, colour box (`e.col`, default #6f5cff) = glow and flash tint. 🌫 Fog (`fogDraw`): a haze thicker at the bottom plus soft drifting clouds of mist; rolls in over 1 s and lifts over `FOG_TAIL` 1.5 s after it ends; Strength = thickness, See-through (default 20%), Angle = drift way and speed, colour box (default #e3e8ef). 💨 Wind (`windDraw`): gust streaks plus tumbling leaves; Angle below 0 blows left; colour box = streak colour. 🧊 Hail (`hailDraw`): ice pellets that bounce once at the ground. 🌈 Rainbow (`rainbowDraw`): 7-colour arc, fades in 1.5 s and out 2 s; Strength = size, Angle = position. 🏜 Sandstorm (`sandDraw`, kind `sand`): sandy haze thicker at the bottom plus streaks and grains blowing across; rolls in 1 s, settles 1.5 s; Angle = way and slope, colour box (default #d8b77a); wind adds to it. 🍂 Falling leaves (`leafDraw`, kind `leaves`): autumn leaves flutter, sway and turn; falling ones finish (`LEAF_TAIL` 8 s). 🔥 Ash & embers (`emberDraw`, kind `embers`): glowing embers float up and flicker out, grey ash drifts down; colour box = glow (default #ff7a1a); `EMBER_TAIL` 3 s. Weathers share the wind (`wxWind`, `wxAng`): an active 💨 Wind on the same frames and layer makes rain, snow and hail lean and fog drift. Combos (`WX_COMBO`, menu values `c:storm`, `c:blizzard`, `c:after`) add several tuned weathers as normal effects. Defaults live in `WX_DEF`, kinds in `WX_KINDS`. More weather effects go in the same group.
- Particles is an extension for Blocks (`EXT` id `particles`, target `blocks`; `ptOn()` needs both added, `ptCatSync` shows or hides the category). Particles category (`particles`, colour #8a0303, Joel designed every block and its shape): particles are drawn in code, never assets. `particle maker` / `preset` give displayable SVG (a `data:` link with the settings in `data-pt`), `implement` turns it into raw `<svg>` code, `add particle` saves it to `PT` (localStorage `oss_particles`, menus show part 1, part 2 … by id; same id replaces). `spawn at x y` shows the last added particle. Positions live in `PTS`, explosion babies in `PTB`; both reset when play starts, when a video with more than one frame loops back to frame 1, and on export (a 1-frame video never resets, or drops would never fall). `spawn` at the same spot while the particle is still out does nothing (`sx`/`sy`). A particle spawned by tapping (not while playing or exporting, `ptLive`) keeps a `home` and goes back there on reset instead of vanishing. Particles show in Edit video (`g`), Watch video and exports. `ptStep` moves them once per frame (fall speed + gravity, stop on the camera's bottom edge), `ptDraw` draws them in `render`. `touching hitbox` needs the Hitbox extension (its menu lists hitboxes). Colour = hex or Scratch-style number (0 to 100 round the rainbow at full colour: 0 with brightness 0 is #ff0000; brightness -100 to 100 goes to black or white, saturation -100 to grey); strips = trail copies, curve = round corners, warp = wobble; the shape's proportions are `ratio () : ()` (Joel swapped width/height for it; stored as `"a:b"`, longer side = 1, `ptWH`; old particles with width/height still work). `cover [part] in particle ()` = the part drawn 60% size on top of the given shell (`p.inner`), id `shell + inner`. `only for all particles that have id ()` (C) runs its mouth once per saved particle whose id starts with the text; inside it `PT_CUR` is that particle, so menus left empty and `spawn` use it (`ptId`). Presets: blood, gore, confetti, water drop, sparks, dust, rubble, smoke, fire sparks, bubbles, tears, sweat drop (a minus fall speed goes up: smoke and bubbles float, fire sparks pop up and fall). Presets carry `vary: 1`: every spawn (and every explosion baby) gets its own size (70–130%, `s.k`) and brightness (±25, `s.db`, `ptBright`), seeded so exports match. Explosions burst wider for bigger and faster particles (`base` in `ptExplode`: 6 + size×1.5 + fall speed×0.6, times stage height / 360). `stop falling ()` stops it where it is (it also stops at the ground: the bottom of the camera view on that frame, `ptGround`). Joel removed `particle () of ()` and `set falling to ()`.
- Hitbox is an extension for Blocks (`EXT` id `hitbox`, target `blocks`, category `hitbox` colour #9966ff, `hbOn()`), Joel designed every block. Hitboxes are invisible polygons in `HB` (localStorage `oss_hitboxes`): `{pts, state: draft|hitbox|saved, vis}`. A points list is text `"x,y x,y"`, a point can carry `#id`, pieces split by ` | `, ` ~live` = keeps warping every frame. `make a point … containing id` adds to `HBG[id]` (reset at frame 1) and gives the group's points; `make an hitbox, with points` uses the id the points carry most (no id = `hitbox N`); repeated points count once (`hbParse`, `with point`, `HBG`); an empty id box in hitbox with id / visualize / delete / save means the last one made (`HB_LAST`, kept in `oss_hb_last`), an unknown id says which hitboxes exist (`hbNone`); a make-hitbox block without ids keeps reusing its hitbox (`HB_BLK`, or same points) so replays don't pile up; `deploy polygon with id` = draft (not seen), `turn polygon to a hitbox` publishes the last one (`HB_LAST`), `save … for later` = kept but not seen. Shape blocks give points around the middle of the stage; `() at x () and y ()` moves a polygon's middle to x, y; `() with id ()` tags every point with the id (spaces become _) and makes them that id's `HBG` group. Flaws/functions: curve, warp, round (`hbFlaw`); `add function [▾]` is a round reporter giving the function for `() with function ()`. Never change a block's shape from Joel's SVG; tapping a Hitbox or Particles command block in the workspace runs it at once and shows its message (`tapCmd`); `hbBreak` slices into pieces with a gap. `visualize hitbox with id ()` is a round reporter (Joel's choice) that gives an SVG picture of the hitbox (the tap bubble shows it); it does not draw on the stage. Every hitbox (not drafts or saved ones) is drawn by `hbDraw` (faint fill, dashed outline, green / red when a particle touches, numbered dots, id tag) on the Edit video (`g`) and Watch video (`wg`) canvases only, never in a downloaded video (Joel's choice). The hitbox point (`HBP`, localStorage `oss_hbpoint`, `hbPointDraw`): a purple crosshair in Edit video only (with the Hitbox extension) that you drag to read block coordinates; its pointerdown is caught on window in the capture phase so it wins over stage dragging. ⌖ Show point / ⌖ Hide point buttons next to Onion (`hbPointUi`, `HBP.show`), shown only with the Hitbox extension. Particles' `touching hitbox` uses `hbTouch` with the particle's size.
- Camera shake extension (`EXT` id `shake`, add-on for Effects, group `fxshake` via `fxShakeUi`): 💥 Hit shake (`hitshake`, a jolt on the first frame that settles by the last), 🌋 Earthquake (`quake`, rolling, eases in and out), 🎥 Handheld (`handheld`, gentle drift); Strength = how hard. All shakes (and the old core `shake`, now scaled to the stage) zoom in just enough that no empty edge shows (in `applyFx`).
- Sound effects extension (`EXT` id `sfx`, add-on for Audio, panel `#sfxpn`, `sfxUi`): `SFX` list (whoosh, punch, explosion, splash, thunder, rain, pop, step, ding, boing), each made in code with an OfflineAudioContext (`sfxMake`, a little random every tap) and added as a normal `AUD` track at the current frame (`sfxAdd`), so it moves in the timeline and goes into exports and zips. No sound files.
- Files extension (`EXT` id `files`, a slot (`adopt: "filespn"`) and an add-on, `flOn()`): `FILES` = `[{id, n, kind: sound|picture|text|other, mime, size, u}]` kept in IndexedDB key `files` (25 MB per file); sounds get a decoded `buf`, pictures an `im` (not saved, `flReady`). Upload (`#flup`) or get from a link (`#flget`, fetch; sites that block it get a message). Sounds: ▶ Play, ＋ Audio, a From Files box on the Audio page (`#flaudpn`), and the sound blocks' menus list them as `f:<id>` (`bkSndList`, `bkSndPlay`). Pictures: ＋ Asset (`lkImage`), Background (`flApplyBg`), and cards next to Scenery's / Edit video's backgrounds (`flBgCards`, class `flbg`). Joel said the Files blocks are coming (he designs them); text files wait for those.
- If saving the project to the browser fails, the corner sign turns red: "Not saved ✗ · use Export project or Zipper" (`doSave`).
- Speed check (v6.68): one frame with all 22 effects ≈ 28 ms, Edit video 60 fps, 1000 frames: changing frame ≈ 30 ms, saving ≈ 5 ms. Projects save to IndexedDB, not localStorage.
- No physics or ragdoll blocks (Joel does that himself): the old `make () able to handle physics` block and the planned `if bounce, play sound` were dropped.
- The Looks blocks `display () at x: () y: ()` and `sticker () at x: () y: ()` were removed (they place assets, which Joel does himself).
- The Zipper no longer loads frames (it was slow); the Upgrades "frames eaten" counter no longer counts for new zips.
